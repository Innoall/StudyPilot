# Project Covenant

- Prefer the smallest existing abstraction that preserves module boundaries.
- Add no dependency without a documented need, owner, version, and security review.
- Each feature includes one success test and one negative test independent of live APIs.
- Safety-critical changes require an ADR and human approval.
- Rules and architecture artifacts must be refreshed within the same sprint as a requirement change.
- Do not generate unattended multi-stage changes; stop at the declared human gates.
